A Raspberry Pi MS-DOS Build

June 2, 2026 • 2123 words • 10 min
raspberrypi homelab project retro

Introduction

As a ‘young’ Millennial, I grew up in the late 90s and early 2000s. Even then, for a variety of reasons, my family often lagged a generation behind on tech. As such, I grew up on late MS-DOS games alongside early Windows games, and due to nostalgia and my growing interest in the fundamental ways computers work, I’ve developed a greater interest in retro computers and games.

Over the early months of 2026, I also found myself developing an interest in single-board computers (Raspberry Pi) and microcontrollers, but I needed a basic project that I could start off with, so I decided to give this a try. I really want to get into retro computing proper, but it’s not a cheap hobby by any means. Instead, I decided to combine these two recent interests as a starter Pi project and build a “nostalgia box” to relive some level of my early childhood experiences on PC!

System Overview

Hardware OS Software
CanaKit Pi Zero 2 W Starter MAX Kit PiOS Lite (64-bit) DOSBox-X | SyncTerm | Windows 2.03 and 3.1 | Various DOS games (mostly shareware for now)

DIFFICULTY LEVEL: Intermediate

Build process

  1. Buy a Raspberry Pi Zero 2 W. If you don’t already have Pi gear, it’d be smart to get some sort of starter kit as I did. My kit included a case, power supply, heat sink, microSD card (64GB, but I swapped it out for a 32GB and will use the 64GB card for a later project), as well as adapters, and a very useful power switch to toggle the system on and off without having to plug/unplug the power supply.
    • You’ll also want to make sure you have a basic USB keyboard with a cord that doesn’t take much power. The typical Raspberry Pi keyboard doesn’t work because it draws too much power. I used a flat Apple keyboard which includes additional USB ports for me to plug in a Raspberry Pi mouse.
  2. Flash the microSD with PiOS Lite (64-bit). Lite is 100% necessary due to the Zero 2 W’s limited RAM (only 512MB). This means you’ll need to be comfortable with a command line, but considering what this project is, I would assume you probably are.
  3. Once you have your Zero 2 W running with PiOS Lite, run updates: sudo apt update && sudo apt upgrade -y
  4. (OPTIONAL) Set up SSH for remote maintenance. Not quite as critical as some builds but might be nice, nonetheless.
  5. In order to get DOSBox-X running, you have to install some basic X11 dependencies. This command will fetch the dependencies needed:
    • sudo apt install xinit xserver-xorg x11-xserver-utils
  6. After those dependencies are installed, you can install DOSBox-X itself through sudo apt install dosbox-x.
  7. Once you have both the dependencies and DOSBox-X installed, you simply run it by typing dosbox-x into the command line.
  8. From here, it’s up to you to familiarize yourself with DOSBox-X, as it does quite a bit differently than classic DOSBox, which is outdated and meant to be used for gaming more than anything.
    • One quick tip to get yourself into an actionable DOS prompt: first, run mount C /home/[username]/[folder with your games and software]. Then, enter C: in the prompt, and you’ll be able to see and use whatever games/software you have in that folder. You’ll have to re-enter that every time you start DOSBox-X but there are ways to set it to do that automatically if you prefer. This article is meant for classic DOSBox but should work for DOSBox-X as well.

Tweaks

GPIO soldering

My kit came with a case that seems like it’d be difficult to remove the Pi from, so I soldered the GPIO headers into the board before I put it into the case. This was my first experience soldering, as I received a solder kit this past Christmas. It was a bit of a pain because I don’t have a clamp to hold things together, but someone in an SBC group on MeWe suggested slotting the GPIO pins into a breadboard and placing the Zero 2 W on top that way. It still wasn’t easy until I got both ends of the headers soldered in but it worked fine after that.

The reason I did this was future-proofing, as I might want to set up other physical tweaks to the system at some point. That, and if I decide I need to wipe this project and use it for something more practical, it’d be easier in case I need those GPIO pins.

Networking

In addition to DOSBox-X, I also installed SyncTerm (sudo apt install syncterm) so that I could dial in to bulletin boards. I figured, if I want this project to give me that 90s computing experience, I’d want to have the ability to use BBSes. Sure, bulletin boards were on their way out by the mid 90s and I didn’t have any experience with them as a kid, but I can’t easily get onto the web with this system so this is a fun alternative to explore.

Terminal change

I changed the typeface for the Linux command line in PiOS Lite, as I wanted it to be a little closer to the look of DOSBox-X to preserve the retro feel and to not be quite as jarring when going between DOSBox-X and the Linux CLI.

To do this, first, I tested a couple different fonts before I committed to one; I used this command to test them:

sudo setfont /usr/share/consolefonts/[fontname]

I settled on using Terminus, as it had a bold 16x32 option, which would come close to what I wanted. Once I decided on that, I ran the following commands to backup the original file and then set the font to be used on boot:

sudo cp /etc/default/console-setup /home/[username]/backup
sudo nano /etc/default/console-setup

Once Nano opens the file, you need to change the FONTFACE and FONTSIZE options. I opted for these:

FONTFACE="TerminusBold"
FONTSIZE="16x32"

From there, once you reboot, the font should be much larger and a bit closer to the default font in MS-DOS, though you’ll get occasional color in the PiOS Lite CLI rather than the monochrome of DOS. If you prefer to go back, compare the text in the backup you made and change the FONTFACE and FONTSIZE attributes back to what they were originally.

Windows installations

I set up both Windows 2.03 and Windows 3.1 on this system. Windows 3.1 was actually my first operating system when I was very young. I didn’t use it for long, as my dad upgraded my PC to Windows 98 not long after its release (not sure why he skipped 95), but even so, 3.1 left a buried mark on my memory and it’s lighter on system resources than 95 or 98 are.

Setting up 2.03 wasn’t difficult at all: it was just a matter of copy-pasting the files into a directory and running the .BAT file that came with it. It could be because I obtained the files from an Internet Archive page that has an in-browser emulation option, but it really was that simple for me. I never used versions before Windows 3, so I don’t know how close that is to the actual process.

As for 3.1, that wasn’t quite as simple. Like I did for the files for 2.03, I used the Internet Archive and the page I found came with six .IMG files only; I assume these are direct images of the floppy disks from an original box installation. I had to do some research on how to install from this setup but ended up getting it up and running with these steps:

  1. Within PiOS, create a dedicated INSTALL folder inside the folder where you’re storing the image files (it needs to be within the DOSBox mount directory from earlier). Also create a dedicated WINDOWS folder within your mount directory wherever you want to be launching Windows 3.1 from.
    1. For example, mkdir /home/[username]/dos/winimage/INSTALL for the INSTALL folder and then mkdir /home/[username]/dos/WINDOWS for the WINDOWS folder.
  2. Launch DOSBox-X, mount your base directory and navigate to the folder with the Windows 3.1 image files.
  3. Run IMGMOUNT A [NAME].IMG
  4. CD to the INSTALL directory and run COPY A:\*.*
  5. CD up once to the image file directory and run IMGMOUNT A -U
  6. From here, you’ll need to repeat the process of steps 3-5 for every image file. This part of the process is done entirely within DOSBox-X.
Important

When doing the copy process, you must make sure that you CD back into the INSTALL directory every time you change image files. You want to make sure all of the files copied from those image files will be placed within the INSTALL directory.

Once you have all the image files’ contents copied to the INSTALL directory, CD back to that directory and run SETUP.EXE. From here, the process is relatively simple for anyone who has installed an operating system. When you get to the part of the installer for printer setup, just select “No Printer Attached”. If you were installing 3.1 on period hardware, it would be feasible to mess around with this part of the process but you’re not going to need or be able to set this up with this particular build. You’ll also want to be sure that you set the installation path to your WINDOWS directory that you set up in step 1.

You’re going to have to ‘reboot’, which will take you back to the command line. Navigate to the WINDOWS directory and type WIN to start Windows 3.1.

Using Windows 3.1

After setup is finished, there’s a pretty solid tutorial for helping you navigate the GUI. If you’ve never used it before, it takes some getting used to, as Windows 3.1 runs differently than every other Windows version from 95 onward. First of all, there’s no start menu or taskbar. Second, most window management occurs within a dedicated program called Program Manager.

You’re likely going to have better luck launching games directly from DOSBox-X. As it stands, you’d need to mess with sound and display drivers if you want to use 3.1 as your ‘home base’ with this project, which isn’t something I’ve done as of this blog post. I might return later and try to mess with drivers if I can find appropriate ones but for now, launching games direct through DOSBox-X is acceptable to me and I can just use 3.1 for fun and the added nostalgia, and maybe even some retro software if they don’t require specific drivers.

Final thoughts

This may not be the most practical build ever, nor is it good for a complete beginner, but it is a lot of fun if you have nostalgia for or interest in retro computing. Sure, you can just run DOSBox-X on your current PC. Sure, you could go scrounging for retro hardware and set up a system that way.

However, with the former, you’re missing out on having a dedicated machine to go to when you want to have a throwback experience. The addition of using PiOS Lite for this project also ensures everything remains within a command line and period-accurate GUIs, adding to the immersion of the project.

As for the latter, it’s far more expensive and challenging to hunt down and build retro hardware. It also requires a lot more skill to do, both at the hardware and software level, and even though I grew up during a more challenging era of computer builds, my dad always handled that when I was young. Even watching a bunch of LGR (my favorite Youtube channel) isn’t going to fully prepare you for just how challenging it is to go the retro hardware route. Not to mention the fact that you’d need to either do some further tweaks or hunt down physical copies of the games and software you want to use on it, and that’s if you manage to get all the drivers set up correctly and judge the hardware requirements properly.

This project is a fantastic middle ground between those two options. You get the immersion of having a dedicated system that’s almost exclusively based in a command line, but with the modern convenience aspect of not having to go through the pain and price of building an actual retro system. The form factor of the Zero 2 W also means you can set it up with an HDMI switch box and just switch between it and your standard display on your PC, rather than having to have a specific area for the system, though again: that does somewhat defeat the immersion of having a dedicated retro system.

Altogether, this was a fun way to kick off my exploration of Raspberry Pi and it won’t be the last project I talk about here!
